# 작업 스케줄 보드

PD 파트의 일정과 투입 리소스를 한곳에서 관리하는 웹 기반 스케줄 보드입니다.
서버 없이 `index.html` 파일 하나로 동작하며, 데이터는 Firebase Firestore에 실시간으로 공유됩니다.

---

## 주요 기능

### 일정 보드

- **2주 보드** — 작업자별 가로 간트 차트. 바를 드래그해 시작일·마감일을 바로 변경할 수 있습니다.
- **월 보드** — 한 달 전체를 달력 형태로 조망. 작업자별 필터 제공.
- **예비 칸** — 담당자가 정해지지 않은 티켓을 임시로 보관하는 행(2주 보드 전용). 통계에는 집계되지 않습니다.
- **작업자 숨기기** — 장기 휴가자를 달력에서 가립니다. 설정은 클라우드에 저장되어 팀 전체에 적용됩니다.

### 티켓

| 항목 | 설명 |
|---|---|
| 프로젝트 | 서든어택 / TFD / 오버워치 / CSO / TF / ARC / 낙원 / SAZ / 공통 |
| 업무 유형 | 라이브 · 오프라인 촬영 · 기획 · 이미지 · 롱폼 · 숏폼 · 언리얼 · 회의 · etc |
| 담당자 | 최대 4명까지 공동 배정 |
| 상태 | 예정 · 작업중 · 보류 · 완료 |

- 업무 유형은 **여러 개 선택**할 수 있고, 유형마다 **수량**을 따로 입력합니다. 예를 들어 `이미지 3 + 숏폼 2`면 총 5건으로 집계됩니다.
- 기획안은 **구글 드라이브 링크**로 첨부합니다. PDF·PPT·슬라이드 등 종류에 맞는 아이콘이 자동으로 붙습니다.
- 본문에 주소를 붙여넣으면 클릭 가능한 링크로 변환됩니다.
- 시작일이 지난 '예정' 티켓은 화면에서 자동으로 '작업중'으로 표시됩니다.

### 부재 관리

휴가·병가·출장 등을 부재 티켓으로 등록하면 보드에 함께 표시되고, 소요일 계산에 반영됩니다.
오전·오후 오프(반차)는 **0.5일**로 계산합니다.

### 대시보드

작업자별·프로젝트별 티켓 수, 업무 유형별 평균 소요일, 분기별 작업 조회, 리포트 텍스트 생성, CSV 내보내기를 제공합니다.

### 월별 MM

프로젝트별 손익 배분을 위한 투입 공수(Man-Month) 집계 화면입니다.

```
작업자 → 프로젝트 → 업무 유형
```

- **영업일** = 그 달 평일 − 병가 · 출산휴가 · 육아휴직 · 전사휴가(공휴일). 개인 오프·연차·반차는 차감하지 않습니다.
- **일정일** = 달력에 잡힌 시작일~마감일 사이 영업일. 겹친 건은 각각 셉니다.
- **MM** = 한 사람의 한 달을 1.00으로 본 프로젝트별 비중. 따라서 **총 MM = 그 달에 일한 인원수**가 됩니다.
- 월 요약, 프로젝트 투입 순위 TOP 3, 업무 유형 순위, 프로젝트별 담당 인원 그래프, 유형 비중 그래프를 제공합니다.
- **마크다운 복사** 버튼으로 전체 표를 한 번에 추출해 노션·슬랙에 붙여넣을 수 있습니다.

## 저장 구조

데이터 유실을 막기 위해 2단계로 저장합니다.

```
수정 → ① 이 기기(localStorage)에 즉시 기록 → ② 클라우드(Firestore) 업로드
```

- **티켓 1건 = 문서 1개**로 저장해 여러 명이 동시에 작업해도 서로 덮어쓰지 않습니다.
- 저장 전 **리비전을 비교**해, 그 사이 다른 사람이 같은 티켓을 고쳤다면 덮어쓰지 않고 **충돌 보관함**에 내 수정을 따로 보관합니다. 나중에 확인 후 되살릴 수 있습니다.
- 서버 저장이 실패해도 변경 내용은 기기에 남아 있고, 연결이 복구되면 자동으로 다시 올라갑니다.
- 새로고침은 **읽기 전용**입니다. 로컬과 클라우드 내용이 실제로 다를 때만 쓰기가 발생합니다.
- 화면 상단 가운데에 **마지막으로 수정·저장된 티켓과 저장 상태**가 항상 표시됩니다.

## 공유

- **읽기 전용 링크** — 상단 `🔗 공유 링크` 버튼으로 `?mode=view` 주소를 복사합니다. 이 링크로 들어오면 조회만 가능하고 생성·수정·삭제가 모두 차단됩니다. 유관부서 공유용입니다.
- **티켓 링크** — 개별 티켓 주소를 복사해 바로 그 티켓을 열 수 있습니다.

## 설치 / 배포

빌드 과정이 없습니다. `index.html` 한 파일을 GitHub Pages 등 정적 호스팅에 올리면 끝입니다.

### Firebase 설정

1. [Firebase 콘솔](https://console.firebase.google.com/)에서 프로젝트 생성
2. **빌드 → Firestore Database** 생성 (위치: `asia-northeast3`)
3. **규칙** 탭에서 아래 내용으로 교체 후 게시

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} { allow read, write: if true; }
  }
}
```

4. 프로젝트 설정 → 웹 앱의 `firebaseConfig` 값을 `index.html`의 `FIREBASE_CONFIG`에 붙여넣기

> 테스트 모드 규칙은 30일 뒤 만료되어 저장이 전부 막히므로 위 규칙으로 직접 교체해야 합니다.
> 현재 규칙은 주소를 아는 사람이면 누구나 읽고 쓸 수 있는 상태입니다. 외부 공개가 필요하면 Firebase Authentication을 함께 적용하세요.
